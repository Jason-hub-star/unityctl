# 공식 Unity CLI 대비 포지셔닝 (v2)

> 2026-07-21, GOAL-unity-cli-benchmark 러닝 B 산출물. 모든 수치는 실측 벤치마크(`benchmark-vs-unity-cli.md`, raw: `benchmark-raw/results.ndjson`) 인용 — 미검증 수치 사용 금지 원칙(출품 문서 §6.5) 준수.
> 결과보고서·접수 카피 반영은 별도 사용자 승인 후 진행.

## 한 줄 메시지

**Unity가 공식 CLI를 내놨다는 것은 "AI 에이전트가 에디터를 제어한다"는 unityctl의 문제 정의가 옳았다는 시장 검증이다.** unityctl은 같은 문제의 범용 명령층에서 경쟁하지 않고, 실측으로 증명된 **에이전트 헤드 층**(빠른 왕복·토큰 규율·검증 폐루프·구버전/무계정 지원)에서 승부한다.

## 공식 스택 현황 (2026-07 실측 기준)

- **Unity CLI 1.0.0-beta.2** (experimental): 에디터 설치/관리, `unity open`, `unity auth` — Hub 대체 성격.
- **com.unity.pipeline 0.3.1-exp.1** (experimental): localhost HTTP로 실행 중 에디터 제어, 140개 명령(실측 `unity list`), Roslyn `eval`, 커스텀 `[CliCommand]`.
- 제약: **Unity 6.0+ 전용**, pipeline 사용에 **Unity 계정 로그인 필수**, 전 구성요소 experimental/beta.

## 실측 비교 — 같은 에디터, 같은 태스크 (8태스크 16셀)

동일 Unity 6000.0.64f1 세션에 양쪽 브릿지를 동시 설치하고 같은 작업을 실행했다. unityctl 0.5.0 @ be84722.

| 실측 항목 | unityctl | 공식 CLI | 의미 |
|---|---|---|---|
| 씬 계층 읽기 (T1) | **286ms / 919B** | 617ms / 1602B | 2.2배 빠르고 43% 작음 — summary-by-default 토큰 규율 |
| play 진입→콘솔→정지 (T4) | **965ms** | 2588ms | 2.7배 빠름 — 에이전트 반복 루프의 왕복 비용 |
| 라이브 C# 다중 문장 (T7b) | 파서 거부 (설계 한계) | **2634ms 성공** | 공식 Roslyn eval의 실질 우위 — 흡수 로드맵 P1 |
| 무인 에디터 테스트 실행 (T6) | **1 passed (4.2s)** | Total 0 **가짜 성공** | 무인 조건에서 공식 Test Runner 연동이 헛돎 |
| 도메인 리로드 생존 (T8) | 실패 (141.7s 타임아웃) | **739ms 생존** | 우리 P0 결함 — 수명주기 재설계로 흡수 (아래) |
| 스크린샷 (T5) | **성공** (카메라 0개여도 뷰 캡처) | 실패 "No camera found" | 에이전트 관대함 vs 조기 실패 |

읽는 법: **양쪽 모두 이기고 지는 셀이 있다.** 이 정직한 표가 곧 신뢰성 논거다 — 우리는 경쟁 도구의 우위(eval, 리로드 생존)를 인정하고 흡수 로드맵으로 전환했으며, 우리 결함(T8)은 같은 날 CTL-FEEDBACK에 등재해 수정 계획을 세웠다.

## 공식 CLI가 대체하지 못하는 것 (심사 예상 질문: "공식이 있는데 왜 필요한가?")

1. **지원 범위** — 공식 pipeline은 Unity 6.0+ 전용. unityctl은 2021.3+를 지원해 현업 LTS 프로젝트(2021/2022)에서 지금 쓸 수 있는 유일한 선택지.
2. **무계정·완전 로컬** — 공식은 `unity auth login`(Unity 계정) 필수. unityctl은 계정·네트워크 없이 동작 — 폐쇄망 CI, 교육 현장, 라이선스 정책이 엄격한 조직에서 결정적 차이.
3. **에이전트 신뢰성 설계** — 공식 CLI는 잘못된 인자를 **조용히 무시하고 성공을 반환**한다(실측: `name=X` 형식 인자 무시, 무인 상태 테스트 0개 실행 후 success). AI 에이전트의 검증 루프에서 가짜 성공은 명시적 실패보다 위험하다. unityctl은 실패를 실패로 보고하고, 응답에 undo 그룹·씬 dirty 상태를 동봉한다.
4. **토큰 경제** — 같은 정보를 더 작게(T1 43% 절감, 콘솔 dedupe 25% 절감 실측). LLM 컨텍스트 비용이 곧 운영비인 에이전트 시대의 설계 원칙.
5. **공간 그라운딩·검증 폐루프** — `spatial describe/check`(월드 AABB·술어 판정으로 AI의 공간 착각을 수치로 차단), `workflow verify`/`playSmoke`(스크린샷·콘솔·검증 번들). 공식 140개 명령에 대응물 없음.
6. **오픈소스 거버넌스** — MIT, 920개 자동화 테스트(2026-07-21 실측), 3-OS CI. 공식 스택은 전체가 experimental이며 소스 기여 경로가 없다.

## 정직한 열세 → 같은 날 전부 흡수 (v2 재측정으로 검증)

v1이 확인한 열세 5건을 벤치마크 당일 구현·재측정했다(`benchmark-vs-unity-cli.md` "v2 재측정" 참조). **경쟁 도구와의 정면 비교 → 열세 인정 → 당일 상환 → 수치 재증명**이 이 프로젝트의 개발 속도와 절차를 동시에 보여준다.

| 순위 | 항목 | v1 실측 (열세) | v2 실측 (흡수 후) |
|---|---|---|---|
| P0 | 무인 에디터 브릿지 수명주기 | T8 실패 141.7s vs 공식 739ms | 리로드 생존 313~516ms, 무킥 자동 기동 |
| P1 | 다중 문장 C# (eval) | 파서 거부 vs 공식 2,634ms | `exec eval` 1,755ms — 공식보다 33% 빠름, opt-in 게이트 |
| P2 | ObjectRef 리졸버 통일 | 이름 타깃 거부 (2콜 우회) | 이름/경로/globalId 통일, 1콜 415ms |
| P3 | 친화 속성명 | `mass` 실패, 재시도 강제 | `mass` 첫 시도 358ms + 실패 시 후보 목록(양쪽 유일) |
| P4 | 플레이어 런타임 | 공식 고유 | `runtime status`/`logs` — dev 빌드 전용, 라이브 검증 |

잔여 공식 우위는 runtime hot-reload/input-sim뿐이며 백로그로 관리한다.

## 출품 서사 연결 (§6.5 확장)

기존 비교표(Unity AI / Unity MCP / unityctl)에 **공식 Unity CLI 열을 추가**할 때 이 문서의 실측 수치를 사용한다. 서사 축:

- Unity AI = 에디터 안 사람용 보조 (구독 종속)
- 공식 CLI = 범용 명령층의 공식화 (Unity 6+, 계정 필수, experimental) — **우리 문제 정의의 검증자**
- unityctl = 에이전트 헤드 (빠른 왕복 + 토큰 규율 + 검증 폐루프 + 구버전/무계정 + MIT)

시연영상·발표에서 쓸 수 있는 강한 장면: 같은 에디터에서 두 도구를 나란히 실행한 실측 벤치마크 자체 — "공식 도구와 정면 비교를 스스로 수행하고 결함을 공개한 팀"은 완성도·신뢰성 평가 항목에 직접 닿는다.
